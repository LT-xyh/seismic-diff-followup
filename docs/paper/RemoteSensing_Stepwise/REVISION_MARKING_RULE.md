# Manuscript revision marking rule — mandatory for future revisions

**Status:** author-approved on 2026-10-12. This policy applies to the active BG-RFM Remote Sensing stepwise manuscript and all subsequent manuscript revision steps. It is not a request to alter historical AAAI source files or previous frozen manuscript branches.

## Canonical source and visibility

- The active manuscript entry is `main.tex` under `docs/paper/RemoteSensing_Stepwise/`.
- Set `\BGshowrevisionstrue` in `main.tex` for the **marked editorial PDF**, in which added/revised prose is blue and newly added/revised figures are outlined in blue.
- Set `\BGshowrevisionsfalse` for the **clean submission PDF**. Both modes render identical scientific text, equations, numbers, and original figure imagery.
- Inline/additive or replacement scientific prose: `\BGRevAdd{...}`. Mark the *entire paragraph that was newly added or revised*, not merely one word.
- Newly introduced or modified figure: `\BGRevFigure{...}` around its graphical body, and `\BGRevAdd{...}` around the new/updated caption where safe.
- Changed tables/equations: use an appropriate marked environment or a clear `% BG-REV <ID>` source marker and an entry in the revision ledger. Do not wrap fragile LaTeX environments in a simple text macro.
- Removed/replaced content: retain the earlier complete active source snapshot and record old/new placement in the ledger. Do not reintroduce removed claims into a PDF just to show strikeout.
- Journal metadata/title/other publisher moving arguments: where inline color would risk breaking metadata, mark the source with `% BG-REV <ID>` and document it in the ledger instead.
- Do not color the original AAAI archived source, baseline evidence files, or unrelated project records.

## Required process for each edit

1. Start from the last author-approved stepwise branch; create a *new branch* and active content copy for an independently reviewable step. Keep the earlier step and historical AAAI source immutable.
2. Make only author-approved edits; assign a stable `BG-REV` ID to each modified or added paragraph, table, figure, equation or administrative metadata field.
3. Mark all changed scientific content in the **active working manuscript** using the macros/source markers above.
4. Add a ledger entry with original location, new location, exact change type, whether experimental/numerical content changed, and applicable Git commit.
5. Review a marked PDF (preferably with changed portions highlighted) and separately verify that the clean PDF can be generated by the toggle without changing semantic content.
6. Before journal submission, turn **all visible change markings OFF**, check the PDF visually, and preserve the annotated manuscript as an internal author-review artifact.
7. Never interpret a formatting/CI failure as authorization to rewrite scientific paragraphs or substitute experimental results.
